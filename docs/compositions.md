# 本地图文组

图文管理只读取 Moments 中已保存的精选照片，不依赖旅行预览缓存。可以选一天或多个不相邻的日期，跨城市也可以。未勾选公开的日期同样可在本地使用；**保存图文组不等于允许公开**。图文组不进入 Git、公开 ZIP、Release 或 Pages。

## 使用

1. 启动 `pixi run app`，进入 **图文管理**，点击 **新建**。
2. 在左侧勾选一个或多个精选日期；可按日期、城市、地点搜索。
3. 从下方精选来源选图。组内图片独立保存，顺序即后续阅读顺序；拖动图片或握柄调整顺序，插入线标记落点，跨行也可以。叉号移出，不取消 Moments 原来的精选。握柄或图片聚焦后也可用 Alt+左右方向键排序，Alt+Home/End 移到首尾。
4. 在 **基本信息** 填写必填的 **标题**、**地点**；地点参考按中英文逗号、顿号等拆成独立小方块，点击只加入该地点。时间、城市默认从所选日期读取，各自有默认勾选的 **自动填写**；取消后可以手动修改日期范围或城市。每次增减来源日期都会重新勾选自动填写并更新为标注值，避免沿用上一选择的手动值。手动设置会随图文组保存、重开保留。
5. **文案标题**、**文案正文**均可留空或手写。图文组标题是内部管理名，不等同于文案标题。
6. 点击组内图片即可选中，边框和勾号标记当前图片，右侧九宫格随之切换并只修改该图滤镜；每张组内图片下方有自己的强度滑条。魔棒才会将当前滤镜应用到整组，并保留各图独立强度；原色可还原。点击放大镜打开大图，支持方向键与 Esc，不会改变调色选中项。

   组内大图右侧同样有九宫格滤镜和强度滑条，只修改当前大图对应的图片；切换图片时显示各自设置，关闭大图后保留修改，再点“保存图文组”统一落盘。强度方向键只调数值，不翻页；拖动强度时大图预览有短暂防抖，避免密集重编码。精选来源大图保持只读，不改变来源照片。
7. 点击 **保存图文组**。顶部本地目录从“尚未保存”变为实际完整路径，可点击复制图标。左侧可重新打开、重新载入或删除；删除只移入本地 `.trash/`，不影响原图、标注和精选。

离开图文页再回来会保留未保存草稿；新建、切换图文组、刷新或关闭网页有丢弃提醒。外部 Agent 修改文件后，点击重新载入再继续编辑；旧页面直接保存会收到冲突提示，不覆盖外部修改。

## 计划发布日期

文案区的 **计划发布日期** 默认勾选 **自动填写**。创建图文组时，从创建当天的本地日历日期开始查找空闲日期；当天已有其他组排期，就顺延一天，连续占用则继续顺延。拍摄日期不参与排期。新组保存时服务端再次核对，避免不同页面同时新建时占用同一天。

取消自动填写后可手动指定日期，包括与其他组相同的日期；再次勾选会按本组创建日及其他组排期重新计算。普通编辑、重新载入或修改照片来源不会重排已保存的日期。左侧图文组列表也显示排期。

旧v1清单缺少新字段时，按创建时间顺序兼容生成建议，读取不会改写原文件；下次保存才记录日期和自动模式。排期与其他信息一起点 **保存图文组** 保存，只是本地计划，不会自动调用平台或发布内容。`文案.txt`仍只包含文案，不插入计划日期。

## 数据目录

默认路径可在私密 `config/local.yaml` 的 `storage.compositions` 配置；缺省为 `data/compositions`。必须在仓库内被忽略的 `data/` 下，且不能与数据库、缓存、备份或公开导出目录重叠。

```text
data/compositions/
  2024-05-02至2024-05-03_深圳、上海_街巷小记/
    group.json               唯一权威清单，UTF-8，schemaVersion=1
    文案.txt                  文案标题与正文，可直接打开复制
    base/
      2024-05-03_0001_底图_v0001.jpg 已纠正方向、去元数据、最长边2400px的底图
    images/
      0001_2024-05-03_v0001.jpg 顺序号、拍摄日期、保存版本；当前滤镜成品
    agent-request.md         点击“准备文案”后生成的任务；再次保存时移除
  .trash/
    <原目录名>_删除于<时间>/   被删除图文组，可在关闭App后移回上一级恢复
```

目录和照片文件名不使用hash。成品名以4位补零的当前顺序号开头，按文件名排序就是图文顺序；`v0001`为保存版本，新版本先写新图片再原子提交清单，成功后只保留当前成品，未改滤镜的图直接复用成品字节而不重复调色。`base/` 是重编码派生图，不是原图文件副本；每次调色都从底图开始，不叠加上一版滤镜。保存失败不替换旧清单。

目录结构固定；首次保存用“日期_城市_标题”命名，多日显示起止日期，多城市用顿号连接，未填城市显示“未标注城市”。标题和城市会移除路径非法字符、限制长度；重名自动加`_2`、`_3`，不会覆盖。命名后修改标题、地点、日期或滤镜不会再改变目录名。旧hash目录和文件仍可读取，下次在App保存时自动转换为可读命名，未保存不会批量迁移。内部ID仅供稳定引用，不作为新目录或图片文件名。

页面显示服务端实际解析的保存路径；已保存组即使有未保存修改，仍显示原目录，新建且从未保存才显示“尚未保存”。发图文时从`images/`按文件名选图，从`文案.txt`复制文案即可。文本是`group.json`的只读镜像：请在App或清单中修改，保存/重新载入后更新文本；直接改文本不会回写清单。

已保存组保留图片快照，即使后来取消原精选或原图暂不可用，仍能查看、修改文案、排序和重新调色；新增照片仍必须来自当前精选。备份应复制整个 `compositions/`（包括图文清单和图片），而不只是标注数据库。

## group.json 约定

机器可读格式见 [composition-v1.schema.json](composition-v1.schema.json)。跨字段约束由App服务额外检查：照片必须属于所选日期、ID与相对引用一致；自动模式从标注推导城市时间，手动模式校验日期范围及城市列表。

| 字段 | 说明 |
| --- | --- |
| `schemaVersion` | 整数，目前为 `1` |
| `id` | 内部稳定32位UUID，与可读目录名无关；不可修改 |
| `revision` | App 每次保存递增；Agent 不修改 |
| `createdAt`、`updatedAt` | UTC ISO 8601 时间；App 维护 |
| `title`、`location` | 必填字符串，最多140和300字符 |
| `captionTitle`、`caption` | 可选文案标题/正文，空值统一为 `""`；最多140和20000字符 |
| `publishDate` | 计划发布日期，`YYYY-MM-DD`；v1兼容可选，当前保存时写入 |
| `autoPublishDate` | 是否自动安排计划发布日期，默认true；独立于拍摄时间、城市的autoFill |
| `sourceDates` | 排序去重的原始拍摄日期键，`YYYY-MM-DD` |
| `days` | 每个来源日期的快照：`captureDate`、标注中的展示 `date`、`cities`、`places` |
| `time` | `start`、`end`、`dates`；自动时为来源展示日期，完整保留非连续日期；手动时为用户指定的范围和端点列表 |
| `cities` | 自动时按来源日期去重，手动时为用户指定的城市列表；没有城市时为空数组 |
| `autoFill` | `{ "time": true, "cities": true }` 控制两个字段的自动填写；v1新增兼容可选字段，旧文件缺失时均按true处理 |
| `photos` | 有序数组；数组顺序就是图文顺序，不通过文件名排序 |

每个 `photos` 条目包含：

```json
{
  "id": "000000000000000000000001",
  "captureDate": "2024-05-02",
  "relativePath": "archive/202405_a/example.jpg",
  "baseFile": "base/2024-05-02_0001_底图_v0001.jpg",
  "file": "images/0001_2024-05-02_v0001.jpg",
  "filter": { "version": 1, "preset": "warm-film", "strength": 65 }
}
```

示例内容均为虚构。`relativePath` 是本地来源引用，不是公开字段；只有 `baseFile` 和 `file` 相对当前图文组目录。API 临时增加 `directory`（实际本地目录）、`etag`（清单原始字节的 SHA-256）、`src` 和 `thumbnail`，这些不写进清单，也不进入公开产物。修改和删除必须携带最新 `etag`；外部直接改 JSON 也会使旧页面失效。

## 文案 Agent

**准备文案**是独立按钮：先保存当前图文组，再生成 `agent-request.md`，弹窗可复制对应指令。此步骤不运行 Codex、不调用 API、不上传图片、不自动写文案或发布。

以后让 Agent 读取该文件和 `photos` 顺序指定的 `images/`；只修改 `group.json` 的 `captionTitle`、`caption`，保留所有其他字段，使用 UTF-8 合法 JSON，推荐临时文件写好后原子替换。不要读取整个照片库、数据库或配置。已有手写文案不能未经确认覆盖，也不要编造票价、开放时间、人物或旅行经历。

## 预设滤镜

选择器固定为9个预设（含原色），3行3列完整展示，不在滤镜区内滚动：

| 预设 | 风格方向 |
| --- | --- |
| 原色 | 不改变色调 |
| 清透日常 | 轻微提亮、清晰对比 |
| 暖调胶片 | 暖色、柔和饱和度 |
| 冷调城市 | 冷色、稍高对比 |
| 柔雾复古 | 低对比、抬黑位 |
| 鲜活风景 | 增加饱和度与对比 |
| 黑白纪实 | 标准黑白层次 |
| 森系青绿 | 柔和绿色倾向 |
| 青橙电影 | 冷阴影、暖高光分离色调 |

历史版本的其他11个预设不再出现在选择器中，但配方及名称仍兼容。已有图文组的效果、强度和成品保留，仍可查看、重新调强度和保存，不会自动变成原色；JSON Schema保留这些历史ID。

各图强度0–100，0为原色；配方版本1使用 Pillow 的亮度、对比度、饱和度、通道色温、黑位与线性混合，新电影效果增加明暗分离色调。原有7个配方不变。缩略图、大图及保存成品共用同一配方，不用仅CSS预览冒充成品。

风格方向参考 [Instagram 官方的柔和色彩滤镜介绍](https://about.fb.com/ja/news/2014/12/instagram_five-new-filter/)、[VSCO 的暖胶片与黑白风格](https://www.vsco.co/features/photo-filters) 和 [VSCO 低对比、淡化风格](https://www.vsco.co/vsco/journal/low-contrast-looks)。这里只借鉴通用视觉方向，系本项目自定义配方，不是这些产品的官方滤镜或商业 LUT 复刻；没有下载第三方照片或预设文件。

历史扩充另外参考 [VSCO 预设指南](https://support.vsco.co/en/articles/12698471-preset-guide) 和 [Darkroom 官方预设目录](https://darkroom.co/presets) 的风格分类；当前选择器只保留上述9种，没有把自定义配方宣称为这些产品的官方滤镜。

## 验证

`pixi run test` 运行包括图文模块在内的全部单测与构建。另有隔离的桌面浏览器测试：

```powershell
pixi run npx playwright install chromium
pixi run npm run build
pixi run npx playwright test
```

浏览器测试自动在18765端口启动合成照片、临时SQLite和临时图文组，不加载 `config/local.yaml`，不使用真实库。完成自动停服；截图和临时文件都在被忽略的 `.pytest_tmp/`。测试覆盖1100/1440/1920px桌面、图片实际加载与滤镜像素变化、选图保存、重新打开、大图、文案和Agent交接。
